# save-prompt — 作業記録を保存して main へ push する

- 作成日: 2026-09-27
- 更新日: 2026-09-27

配布元リポジトリの docs/prompt/ に、この会話の依頼内容と結果を記録し、全変更を main へ反映します。実記録（生徒の記録）ではなく、教材整備の作業記録です。

## 1. 記録ファイルを作る

1. Asia/Tokyo の今日の日付を YYMMDD で求める（例: `TZ=Asia/Tokyo date +%y%m%d`）。
2. 題名は、依頼内容を表す短い日本語にする（例: 教材整備、書込対応への改訂）。
3. ファイル名の規則:
   - 同じ日付のファイルが docs/prompt/ にまだなければ `YYMMDD-題名.md`。
   - 同じ日付のファイルが既にあれば連番を付ける。既存ファイルに連番がなければ `git mv` で `YYMMDD-01-元の題名.md` に改名し、新しいファイルは `YYMMDD-02-題名.md` とする。既に連番があれば次の番号を使う。
   - 改名するときは、そのファイルへのリンクが他にないか `grep -rn 'docs/prompt/' --include='*.md' .` で確認し、あれば直す。
4. 本文の構成（既存の記録に合わせる）:

```markdown
# 題名

- 作成日: YYYY-MM-DD
- 更新日: YYYY-MM-DD

## ユーザーの依頼

（この会話でユーザーが送ったプロンプト本文。要約せず、原文のまま。複数あれば送られた順に見出しか区切りを付ける。個人情報や認証情報が含まれていれば伏せる）

## 回答と実装

（何を調べ、何を変えたか。追加・改名・削除したファイル、方針の変更点、ユーザーへの報告の要点）

## 検証と確認範囲

（実行した検査とその結果、未検証のこと。実アカウントでの操作や外部サービスの動作を確認済みにしない）

## コミットとpush

（対象ブランチ、コミットに含める範囲。コミット識別子は push 後に完了報告で伝える）
```

5. 作成日・更新日は Asia/Tokyo の今日。モデル名やセッションの内部識別子は書かない。

## 2. 検査する

```
pwsh -NoProfile -File scripts/check-docs.ps1
```

pwsh がない環境では、相対リンク・日付欄・架空表示を同等の方法で確認し、その旨を記録に書く。失敗したら直してから進む。

## 3. コミットして main へ push する

1. `git status` で対象を確認し、`git add -A` で全変更（作成した記録を含む）をステージする。
2. 変更内容が分かるコミットメッセージでコミットする。
3. 現在のブランチが main でなければ、main を最新にしてから作業ブランチの内容を main に取り込む（fast-forward できなければ通常のマージ）。履歴の書き換えや強制 push はしない。
4. `git push -u origin main` を実行する。作業ブランチがあればそれも push する。ネットワークエラーなら 2s・4s・8s・16s の間隔で最大4回まで再試行する。
5. 拒否された場合（保護ブランチ、権限不足）は、保護解除や強制 push で回避せず、原因と未反映の範囲をユーザーに報告する。

## 4. 報告する

保存したファイルのパス、コミット識別子、push 先ブランチ、検査結果、未検証事項を短く報告する。
