# 移行した原記録を変更せずに確認する

- 作成日: 2026-09-27
- 更新日: 2026-09-27

本人は[移行確認メモ](migration-checklist.md)で対象を選びます。以下はAIや作業を支援する人向けの検査方法です。JSONやコマンドの手入力を本人に毎回求めません。コピーを実行するプログラムではありません。

## 文書検査と移行検査の違い

`scripts/check-docs.ps1` は新しい教材・用紙・記録の日付とリンクを検査します。ルートの legacy/ 以下は原記録として扱い、新しい日付欄を要求しません。旧リンクの問題は REVIEW として報告し、原文を修正しません。検査成功は旧記録のリンク解決や移行完了を意味しません。REVIEWが出た参照を移行確認メモへ記録します。

`scripts/check-migration.ps1` は本人が許可した一覧だけについて、コピー元とコピー先のSHA-256一致を確認します。元の一覧外の本文は読みません。コピー先に一覧外のファイルがあれば失敗します。リンク先へのアクセス、AI利用許可、日付の意味や外部資料の権限は人が確認します。

## 許可した対象一覧

自分用Privateの profile/ など、コピーするまとまりの外にJSONを保存します。元と先の配置は同じにするため、pathは両方のルートからの相対パスです。kindは record（原記録）、derived（要約・報告）、reference（教材等）。referenceを本人の実績に数えません。利用停止・対象外のファイルをfilesへ入れません。

```json
{
  "version": 1,
  "source_repository": "本人が確認した元の保存先",
  "source_revision": "本人が確認した版・コミット",
  "files": [
    { "path": "experiences/2026/260927-note.md", "kind": "record" },
    { "path": "questions.md", "kind": "record" }
  ]
}
```

source_repositoryとsource_revisionは対応確認用で、ツールはGitHubへ接続しません。指定したローカルのコピー元がその版か、作業者が別に確認します。実際のPrivate URLを配布元へ送らないでください。

```powershell
pwsh -NoProfile -File scripts/check-migration.ps1 -Source 'コピー元の確認用フォルダ' -Destination 'コピー先のlegacy/teens-01' -Manifest '許可した対象一覧.json'
pwsh -NoProfile -File scripts/check-docs.ps1
```

旧AGENTS.md、CLAUDE.md、.git、.github、.claude、.agents、.codexは拒否します。ルート外のパス、重複、シンボリックリンク等を拒否します。検査はファイルを修正しません。

## 完了の確認

- 内容一致の結果と、元の版・コピー先を確認メモへ残す。
- 新しい入口から過去の記録へたどり、相対リンクの問題を解決済み／対象外／未確認に分ける。
- 外部原本は新しい利用者の権限で実際に開く。開かなければ未確認とする。
- 元記録とそのコピー・要約を重複集計しない。利用停止を移行先にも反映する。
- 新しい保存先へ新規記録を保存し再表示するまで、通し確認済みとはしない。

原記録にあとから訂正が必要になった場合は、移行時の控えを保ち、訂正日と理由を別に残します。元と先の内容が変わったのに、移行時の一致結果を現在も同一である証拠として使いません。
