# 小学生版から中高生版へ引き継ぐ

- 作成日: 2026-09-26
- 更新日: 2026-09-26

**一番のおすすめは、新しいPrivateリポジトリへ、小学生用リポジトリの内容をコピーする方法です。** 中高生版のテンプレートから新しい保存先を作り、そこへ小学生版で残した文章・問い・作品を引き継ぎます。小学生版の保存先を残したまま、中高生版の用紙とガイドで記録を続けられます。

当時の文章・ファイル名・日付はそのまま使えます。過去の記録を新しい用紙へ書き直す必要はありません。コピーする範囲は本人と確認します。

引き継ぐ元は、[小学生版の公開テンプレート](https://github.com/risan-education/my-portfolio-elementary)から以前作った**自分や保護者のPrivateリポジトリ**です。公開テンプレートの examples/ は架空例なので、本人の記録として取り込みません。

## おすすめの進め方

1. **中高生版から、新しいPrivateリポジトリを作る。**
2. **小学生用リポジトリの内容を、元の配置を保ってコピーする。** 本人が引き継ぐと決めた記録と、必要な参照先をまとめます。
3. **新しい保存先で、本文・日付・リンクが保たれていることを確認する。**
4. **ChatGPTに新しい保存先を伝え、中高生版で記録を続ける。**

ChatGPTやGitHubの既存アカウントは引き続き使えます。契約し直す必要はありません。新しく用意するのは、中高生版の記録を保存するPrivateリポジトリです。

## 方法の比較

| 今の状況 | 方法 | 残せるもの・注意点 |
| --- | --- | --- |
| **まずおすすめする方法** | **A. 新しいPrivateへ、小学生用リポジトリの内容をコピーする** | 小学生版を残して中高生版を始められる。本文のコピーだけでは過去のGit履歴は移らない |
| 同じURL・保存先で続けたい | B. 同じリポジトリに中高生版の案内を取り入れる | 元の配置とGit履歴を保ちやすい。教材と自分の記録を比較して更新する |
| 保護者が所有している同じノートを本人へ渡したい | **C. 所有者を変更する** | 内容の更新とは別の操作。本人が管理できる年齢・権限・共有範囲を確認 |

高校進学時も同じ用紙で続けられます。年齢が変わっただけで再移行する必要はありません。以下の手順はChatGPTに案内してもらえます。保存能力は[接続確認](connection-check.md)で確かめ、読み取り専用なら[手動保存](manual-editing.md)を使います。

## 始める前に、本人と選ぶ

1. 元のPrivateのURL・所有者・ブランチを確認する。本文と外部原本を[バックアップ](backup-and-restore.md)し、控えが開くことを確かめる。
2. 本人が引き継ぎたい記録、利用停止したい記録、AIへ渡してよい範囲を選ぶ。対象外の本文を、仕分けのためにChatGPTへ渡さない。
3. 選んだ記録が参照する元記録・作品・所在メモも確認する。追加でコピーする参照先は本人に利用範囲を確認する。
4. [引き継ぎ確認メモ](migration-checklist.md)の項目を、自分用の profile/YYMMDD-handover.md などへコピーし、元と先の対応を残す。

小学生版と中高生版のファイル名は、共通の **YYMMDD-xxx.md** 形式です。YYMMDDは西暦の下2桁・月2桁・日2桁で、例えば2026年9月1日の記録は `260901-shadow.md` です。移行時に日付形式を変換する必要はなく、元のファイル名と参照リンクを保って引き継ぎます。

本文の活動日・記録日・作成日・更新日はYYYY-MM-DD形式のまま保持します。移した日は確認メモへ書きます。フォルダも今の形を保ち、年別への一括移動をしません。独自の名前で残した既存記録も、移行に伴う一括改名は不要です。

## A. 新しいPrivateへ、小学生用リポジトリの内容をコピーする（おすすめ）

### 1. 中高生版の新しい保存先を作る

[はじめ方](getting-started.md)の手順5に沿って、[中高生版の公開テンプレート](https://github.com/risan-education/my-portfolio-teens)から新しいPrivateを作ります。作成先の所有者・URL・Private表示を確認してください。テンプレートを複製した後に、小学生用のPrivateから自分の記録をコピーします。

> 中高生版のテンプレート https://github.com/risan-education/my-portfolio-teens から、新しいPrivateリポジトリを作り、小学生用の記録を引き継ぎたいです。既存のアカウントを使って準備する手順を教えてください。小学生用の保存先は［旧PrivateのURL］です。元の保存先は残してください。

新しい保存先のAGENTS.mdをChatGPTに読んでもらい、準備します。コピー元とコピー先のURLは区別して伝えます。

### 2. コピーする内容と置き場所を決める

新しい保存先のREADMEやquestions.mdと、旧版で記入した同名ファイルがぶつかる場合があります。その場合は、旧記録を **legacy/elementary-01/** などの未使用フォルダにまとめ、元の保存先から見た配置を保ちます。legacyは過去の記録を置くフォルダ名の例です。

例えば次のように対応させます。ファイル名・日付は説明用の架空例です。

| 元のPrivate内の場所 | 新しいPrivate内の場所 |
| --- | --- |
| questions.md | legacy/elementary-01/questions.md |
| experiences/260901-shadow.md | legacy/elementary-01/experiences/260901-shadow.md |
| projects/shadow/README.md | legacy/elementary-01/projects/shadow/README.md |
| assets/shadow.md | legacy/elementary-01/assets/shadow.md |

このまとまりの内部で使っている相対リンクは、全体を同じ配置でコピーすれば保てます。**一つのファイルだけを別名にして解決すると、参照元のリンクが切れることがあります。** legacy/elementary-01/ がすでにあれば中身を混ぜず、elementary-02等の未使用の名前を選びます。

### 3. ChatGPTにコピーの案を依頼する

> 元の保存先は［旧PrivateのURL］、新しい保存先は［新PrivateのURL］です。本人が選んだ［対象一覧］を、legacy/elementary-01/へ元の配置ごとコピーする案を作ってください。
>
> 参照先も必要な範囲を一覧にしてください。対象外や利用停止中の記録は自動で追加しないでください。元の名前・本文・日付を保ち、コピー先の既存ファイルを上書きしないでください。元と先の対応、未解決のリンク、外部原本の確認事項を示してください。

### 4. 内容を確認してコピーする

案を確認したら「この対象一覧と保存先でコピーし、引き継ぎ確認メモも保存してください」と依頼します。保存機能がない場合は、[手動保存](manual-editing.md)の方法で反映します。

1. 元と先のPrivateを確認し、ChatGPTには必要な範囲のアクセスだけを許可する。直接コピーできない場合は旧版の控えから本人が選んだファイルを取り出し、新Privateへ手動で配置する。
2. 対象一覧と参照先を見て、本人が引き継いでよいものだけに絞る。外部の写真・動画等は別に扱う。
3. 未使用の保存先に、元の相対的な配置を保ってコピーする。元のファイルを消す操作は同時に行わない。
4. 元と先の本文・日付を比較する。ファイル比較やハッシュ比較が使えれば利用し、コピー日で原記録の日付を変更しない。
5. 新しいREADMEや確認メモから、引き継いだ問いの台帳と代表的な記録へリンクする。新しいquestions.mdは旧版で選んだ問いへのリンクから再開でき、全行の重複転記は不要。
6. 引き継いだ記録から作品・所在メモを開き、新しいアカウントでも外部原本が見られるかを確かめる。
7. 本人が内容と利用範囲を確認したら、新しいAGENTS.mdを読み直して、現在の振り返りを別ファイルに作る。

### 何をコピーするか

| 旧版の内容 | 扱い |
| --- | --- |
| profile/、experiences/、projects/、reflections/、annual-review/ | 本人が選んだ記入済みの記録を原文のまま |
| questions.md、記入済みREADME | 記録として保護。新しい同名ファイルへ上書きせず、元の配置を保つ |
| derived/ | 元記録の利用許可と出典も確認。旧要約と元記録を二重に実績として数えない |
| assets/ | 所在メモを保持。外部原本の所有者・閲覧権限・バックアップも別に確認 |
| 旧templates/・docs/ | 原記録から必要な参照がある場合に同じ配置で残せる。実績としては集計しない |
| 旧examples/ | 配布元の架空例。本人の活動へ変換しない。参照用に残す場合も架空と区別 |
| 旧AGENTS.md・CLAUDE.md・.github/ | 新しい保存先の現行指示へ上書きしない。旧指示書を有効な指示としてlegacy内へ持ち込まない |
| LICENSE | 教材や架空例を再利用する場合は表示を保持する |
| .git/・秘密情報 | 通常のファイルコピーに含めない。履歴が必要なら別途バックアップ方法を選ぶ |

本文のコピーでは旧Git履歴は新しい保存先へ引き継がれません。履歴も手元に残したい場合は[バックアップ](backup-and-restore.md)を確認します。移行完了後の元の保存先を残すか、利用停止するか、削除するかは本人が別に選びます。

### 相対リンク以外に注意する

- /から始まるリポジトリのルート基準のリンク、旧PrivateのURL、端末固有のパスは、まとめて置くだけでは新しい場所を指さないことがあります。
- 移さない記録への参照は、本文を勝手に修正したり対象外の原本を追加したりせず、確認メモに「対象外／未解決」と記します。
- 原記録を保持したまま、確認メモに新しい参照先へのリンクを追加できます。本文のリンク修正が必要なら、元の控えを保ち、本人が指定した範囲で訂正日と理由を記録します。
- legacy内にも用紙や架空例が混在しえます。ChatGPTの検索・要約対象は確認メモで本人が選んだ**実記録**に限定します。

[関連リンクを持つ架空の移行例](../examples/migration/README.md)で配置の具体例を確認できます。

## 古い探究や問いを続ける

旧版の「未着手」「途中」「ひと区切り」「お休み」はそのまま残します。中高生版の新しい記録では「これから」等を選べますが、旧台帳を一括で置換しません。

家庭の探究・単元づくりシートは、6段階へ自動変換しません。保護者の設計案・未実施の活動・AI案は本人の実績にせず、実際に行った記録を根拠にします。高1頃に入試対策を始める際は、その記録も参考に主テーマを一つ選び、[6段階の探究ガイド](inquiry-project-guide.md)で新しい継続計画を作ります。

> 引き継いだ［旧記録へのリンク］を読み、今の私の考えを確認してください。当時の文章は変えず、新しい振り返りの案を作ってください。続ける場合も、どの問いや段階から始めたいか私に聞いてください。まだ実施していない案は未実施のままにしてください。

本人が続けない選択もできます。始める場合は[探究ガイド](inquiry-project-guide.md)、まとめる場合は[ChatGPTへの依頼例](ai-guide.md)を使います。

## B. 今の保存先を使い続ける（別の方法）

同じURLやGit履歴をそのまま使いたい場合に選ぶ方法です。古い原記録の場所を変えず、これからの記録に中高生版の案内を取り入れます。

### ChatGPTに最初に伝えること

次の角括弧部分を実際のURLや範囲に置き換えます。準備や案の依頼では、まだ保存しません。

> 小学生版で使っていた自分用Privateは［元のURL］です。この保存先を使い続けて、中高生版の案内を取り入れたいです。
>
> 参照する配布元は https://github.com/risan-education/my-portfolio-teens です。本人が引き継ぎを認めた範囲は［対象ファイル・フォルダ］です。
>
> 原記録、問いの台帳、元の名前・日付・リンクを保ってください。私の追加ルールや記入済みREADMEを確認し、教材として更新するファイルと、変更しない記録の一覧を見せてください。小学生版だけの探究シートやガイドは消さないでください。

### 取り入れる順番

1. 中高生版を別の場所で開く。自分用へ丸ごと上書きしない。
2. 空欄の templates/、必要な docs/ を比較する。新しい inquiry-project.md や進路探索等を取り入れ、同名の用紙に本人が記入していたら記録として保護し、先に別名の新用紙を用意する。
3. AGENTS.mdを中高生版のルールに合わせる。本人用の保存先・利用範囲や独自の指示を保持し、保護者だけが操作する前提を本人主体へ見直す。Claude CodeやCopilotも使う場合は対応する指示書を揃える。
4. 本人が書いたトップのREADMEやフォルダのREADMEは丸ごと置き換えず、中高生版のガイドと既存記録へ進める入口を追記する。questions.mdは元の行を保つ。
5. 一覧の更新内容を確認して「この案の教材更新を保存してください」と依頼し、保存後に新しいAGENTS.mdを読み直してもらう。
6. 古い記録と参照先を開き、新しい記録を一件作れることを確認する。

必要なガイドは、リンク先も一緒に確認して取り入れます。新しいREADMEだけをコピーすると、そこから案内するページが不足することがあります。[テンプレート更新の手順](template-updates.md)

小学生版だけにある templates/unit-of-inquiry.md、docs/pyp-uoi-guide.md 等を「中高生版にないから」という理由で削除しません。旧版の説明と現在のルールが異なる場合は、新しい入口から現在使う指示書を示します。原記録は当時の文脈のまま読みます。

## C. 保護者から本人へ所有者を移す

中高生版の用紙を取り入れることと、GitHubリポジトリの所有者変更は別です。本人がGitHubの年齢条件を満たし、管理を希望する場合に選びます。[アカウントの案内](github-basics.md)

1. 本人と引き継ぐ範囲・共同編集者・AIへの提供範囲を確認し、バックアップを取る。
2. 管理権限のある保護者が、旧リポジトリの **Settings → Danger Zone → Transfer** で本人のアカウントを移譲先に指定する。
3. 本人が案内に従って受け取り、新URL・Private・既存ファイルと履歴を確認する。
4. 保護者や他の共同編集者、接続アプリ、連携設定を確認し、本人が必要なものを選ぶ。保護者は移譲後も共同編集者として追加されるため、不要なら本人が見直す。
5. ChatGPTには新URLを伝え、本人の接続権限で読み取れるかを確認する。端末側のGit接続先や、お気に入り、外部原本の閲覧権限も見直す。

公式資料: [リポジトリの移譲](https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository)（確認日: 2026-09-26）。実アカウントでの移譲は未検証です。

個人所有のPrivateでは共同編集者に読み取り専用権限を付けられません。閲覧だけなら本人が選んだ資料のコピーを共有する方法を考えます。[公式の権限説明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/permission-levels-for-a-personal-account-repository)（確認日: 2026-09-26）

## 引き継ぎの完了を確認する

[引き継ぎ確認メモ](migration-checklist.md)で、次を確かめます。

- 本人が選んだ記録がそろい、元の本文・日付・名前が保たれている。
- 過去の問いから活動・作品・所在メモへたどれ、外部原本の閲覧も確認できる。
- 同名の新しい記録を上書きしていない。未解決の参照を「確認済み」にしていない。
- 見せない記録・利用停止した記録を、新しい要約やAI向け情報へ再登場させていない。
- ChatGPTが新しい保存先と現行の指示を読み、新しい記録を別ファイルに保存できる。

新しいChatGPTの会話は、旧会話の内容を自動で引き継ぐ前提にしません。新URLと確認メモ、本人が選んだ元記録を指定して始めます。会話履歴を丸ごとコピーする必要はありません。
