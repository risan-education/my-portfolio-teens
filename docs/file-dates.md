# 日付のルール

- 作成日: 2026-09-26
- 更新日: 2026-10-02

| 項目 | 意味 |
| --- | --- |
| 活動日・制作日 | 実際に活動した日・期間 |
| 記録日 | その経験を文章やメモにした日 |
| 作成日 | このファイルを作成した日 |
| 更新日 | このファイルの内容を最後に変更した日 |
| 出典・権限の確認日 | 資料や閲覧権限を実際に確かめた日 |

例えば9月1日の経験を9月3日に紙へ書き、9月5日にファイル化した場合、活動日1日・記録日3日・作成日5日・初回更新日5日です。

ChatGPTが記録を作るときも、以下のルールで日付を記入します。本人は活動日・記録日が合っているかを確認します。

新規のMarkdownは最初の見出しの下に作成日と更新日を置きます。日本時間（Asia/Tokyo）で確認できる日を記入します。活動日の指定がない日々のメモは、会話当日として案に示し「（指定なし。話しかけた日）」と添えます。「昨日」等は会話日から換算し、本人が確認します。本人が「昔のことで日付は分からない」と伝えた場合は未確認とし、今日で埋めません。この既定を制作期間・出典確認日などに広げません。

内容を変えたときだけ更新日を変え、閲覧しただけでは変えません。コピー用 templates/ の日付欄は空欄です。配布日を本人の活動日へ転記しません。

ファイル名は小学生版と共通のYYMMDD-theme.md（YYMMDD-xxx.md、例: 260926-reading.md）に統一し、年間振り返り・要約・作業記録など、どの種類のファイルでも同じ規則を使います。本文の日付はYYYY-MM-DD（例: 2026-09-26）で記入します。小学生版からの移行時に日付形式を変換する必要はありません。

小学生版からそのまま移す原記録は本文・ファイル名・日付を保ちます。移した日や現在の解釈は別の移行メモに書きます。架空例の日付は架空として読みます。Gitの保存日時だけでは活動した事実の証明になりません。

日々の新規記録の推奨先は experiences/YYYY/YYMMDD-theme.md です。既存の直下配置はそのまま使えます。過去の名前とリンクをそろえるための一括移動は不要です。questions.mdの「問いを残した日」は問いを記録した日で、元の活動日とは別です。

legacy/へ引き継いだ旧記録は、作成日・更新日欄がなくても追加を強制しません。移行日は確認メモへ残し、[移行検査](migration-verification.md)で原文保持を確かめます。
