# ChatGPTの接続と保存を確かめる

- 作成日: 2026-09-26
- 更新日: 2026-09-26

契約、アプリのインストール、GitHubへの接続、ファイルの書き込みは別々の段階です。自分の環境でできることを、最初は架空の記録で確認します。

## 接続ごとの違い

| 利用方法 | 記録の作成・整理 | GitHubへの保存 |
| --- | --- | --- |
| ChatGPTへ必要なメモを貼る | 会話で案を作れる | 本文を自分で保存 |
| 通常のChatGPT GitHubアプリ | 許可した記録を読み、案を作る | 公式説明では読み取り専用。自分で保存 |
| ChatGPTデスクトップのCodex等、ファイル編集できる環境 | 選んだフォルダで案やファイルを作る | ローカル編集・GitHub反映を別々に確認 |
| 書き込み対応GitHubツールを使える環境 | 提供される機能の範囲で作成・追記 | 対象権限とmainへの反映を実操作で確認 |

公式資料: [GitHubアプリの読み取り専用の説明](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt)／[デスクトップの開始手順](https://learn.chatgpt.com/docs/quickstart)（確認日: 2026-09-26）。Plus契約やプラグインのインストールは、書き込み権限を保証しません。

## 自分のPrivateで練習する

[はじめ方](getting-started.md)で保存先を作り、AGENTS.mdを読んでもらってから、次を送ります。

> 架空の練習記録の案を作ってください。活動日は2026年9月26日、メモは「紙を折って遊んだ」です。一言メモの用紙を使い、自分用Privateの examples/260926-connection-practice.md に保存する案を見せてください。架空例と明記してください。同名があれば上書きしないでください。

1. 案に「架空」とあること、元メモ・活動日・作成日・更新日を確認する。
2. 「この内容で保存してください」と頼む。保存機能がなければ[手動保存](manual-editing.md)へ進む。
3. GitHubの自分用リポジトリでmainを選び、実際のファイルを開く。AIの返事だけで成功としない。
4. 続けて「この練習記録へ『次は別の折り方を試したい』を本人の希望として追記する案を見せて」と頼む。
5. 案を確認して保存し、元メモが残っていることをmainで再確認する。追記日は実際の日付を使う。
6. このファイルは examples/ に置いたまま、本人の活動の集計・要約から除外する。

同日の追記なら更新日が同じでも構いません。練習後に、自分の実体験を別のファイルとして残します。

## うまくいかないとき

- **Plusなのに保存できない**: 通常のGitHubアプリは読み取り専用です。[手動保存](manual-editing.md)か[デスクトップ編集](chatgpt-desktop.md)を使います。
- **プラグインが見つからない**: アプリ更新、利用画面、プラン、ワークスペースの提供条件を確認します。権限を広げれば必ず出るとは限りません。
- **自分用Privateが一覧にない**: GitHub側の認可で所有者と対象リポジトリを確認します。作成直後は反映に時間がかかる場合があります。
- **AGENTS.mdが読めない**: URLと接続対象を確認します。読めなければ必要な指示書・用紙を添付し、下書きから始めます。
- **mainで見つからない**: 保存先・ブランチ・コミット・push結果を確認します。端末内や作業ブランチへの保存はmain反映と別です。
- **権限や保護で拒否された**: 変更内容を保ち、原因を確認します。保護解除・強制pushは自動で行いません。
