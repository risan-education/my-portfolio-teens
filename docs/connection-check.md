# ChatGPTの接続と保存を確かめる

- 作成日: 2026-09-26
- 更新日: 2026-10-02

アカウント、GitHubへの接続、ファイルの書き込みは別々の段階です。自分の環境でできることを、最初は架空の記録で確認します。

## 接続ごとの違い

| 利用方法 | 記録の作成・整理 | GitHubへの保存 |
| --- | --- | --- |
| ChatGPTの書込対応のGitHub接続 | 許可した記録を読み、案を作る | 対応する作成・追記・コミットを頼む。直接mainか別ブランチかを先に確認 |
| ChatGPTへ必要なメモを貼る（接続なし） | 会話で案を作れる | 本文を自分で保存 |
| ChatGPTデスクトップなど、端末のフォルダを編集できる環境 | 選んだフォルダで案やファイルを作る | 端末内の編集とGitHubへの反映を別々に確認 |
| Claude Code等、別の書き込み対応ツール | 提供される機能の範囲で作成・追記 | 対象権限とmainへの反映を実操作で確認 |

公式資料: [GitHub接続の説明](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt)／[デスクトップの開始手順](https://learn.chatgpt.com/docs/quickstart)。配布元から2026-09-27に編集できたとの実利用報告があります。環境の詳細を揃えた再現検証とは区別し、[確認記録](connection-environments.md)に不足項目を示しています。権限は環境・プラン・版によって違うことがあるので、自分の環境では次の練習で確かめます。

## 自分のPrivateで練習する

[はじめ方](getting-started.md)で保存先を作り、AGENTS.mdを読んでもらってから、次を送ります。

> 架空の練習記録の案を作ってください。活動日は［今日の日付］、メモは「紙を折って遊んだ」です。一言メモの用紙を使い、自分用Privateの practice/ に YYMMDD-connection-practice.md の名前で保存する案を見せてください。架空例と明記してください。同名があれば上書きしないでください。

1. 案に「架空」とあること、元メモ・活動日・作成日・更新日を確認する。
2. 「この内容で保存してください」と頼む。ChatGPTが保存先とコミットの結果を報告する。保存機能がなければ[手動保存](manual-editing.md)へ進む。
3. 保存経路・コミットを確認する。別ブランチ・PRなら説明を受けた方法でmainへ反映してから、GitHubでmainの実際のファイルを開く。端末内・作業ブランチだけならmain未反映。AIの返事だけで成功としない。
4. 続けて「この練習記録へ『次は別の折り方を試したい』を本人の希望として追記する案を見せて」と頼む。
5. 案を確認して保存し、元メモが残っていることをmainで再確認する。追記日は実際の日付を使う。
6. 新しい会話で同じPrivateの指示書と練習記録を読み直せるか確かめ、読めなければ未確認と残す。
7. このファイルは practice/ に置いたまま、本人の活動の集計・要約から除外する。

同日の追記なら更新日が同じでも構いません。練習後に、自分の実体験を experiences/ に別のファイルとして残します。

## 使い始めて迷ったところを確かめる

架空の一件を保存して、一覧から再び開くところまで試します。うまくいかなかった操作は未確認・失敗として残せば十分です。本人の実記録や画面の個人情報を配布元へ送る必要はありません。

- どのページで次に何をするか迷ったか。
- どの質問が答えにくかったか、途中で止められたか。
- 保存したファイルを再び開き、元メモと追記を見つけられたか。
- スマホで完成見本の文章・表・折りたたみを読めたか。

確認日と環境を[接続・保存の確認記録](connection-environments.md)の項目に沿って残します。[保存できないときの会話例](../examples/prompts/short-sessions.md#保存できないとき)も参考になります。

## うまくいかないとき

- **保存を頼んだのに反映されない**: ChatGPTの報告にある保存先・ブランチ・コミットを確認します。接続の権限が読み取りだけの場合は、[手動保存](manual-editing.md)か[デスクトップ編集](chatgpt-desktop.md)を使います。
- **接続機能が見つからない**: アプリの更新、利用画面、プラン、ワークスペースの提供条件を確認します。権限を広げれば必ず出るとは限りません。
- **自分用Privateが一覧にない**: GitHub側の認可で所有者と対象リポジトリを確認します。作成直後は反映に時間がかかる場合があります。
- **AGENTS.mdが読めない**: URLと接続対象を確認します。読めなければ必要な指示書・用紙を添付し、下書きから始めます。
- **mainで見つからない**: 保存先・ブランチ・コミット・push結果を確認します。端末内や作業ブランチへの保存はmain反映と別です。
- **権限や保護で拒否された**: 変更内容を保ち、原因を確認します。保護解除・強制pushは自動で行いません。
