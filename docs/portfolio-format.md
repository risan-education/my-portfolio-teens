# 中高生版・大学版へ引き継ぐ記録の共通仕様

- 作成日: 2026-09-27
- 更新日: 2026-09-27
- 仕様の版: 1.0

これは中高生版で採用する仕様と、大学版 `my-portfolio-univ` の要件定義へ引き継ぐ事項です。大学版は仮の要件定義段階であり、大学版の実装・互換性を確認済みとするものではありません。独自アプリやデータベースは追加しません。

## 共通にすること

| 項目 | 仕様 |
| --- | --- |
| 本文 | UTF-8のMarkdown。特定のAIや独自形式を必須にしない |
| 新しい記録の名前 | YYMMDD-theme.md。活動日不明は date-unknown-theme.md、衝突時は -02 等 |
| 新しい記録の日付 | 活動日・記録日・作成日・更新日を区別し、本文ではYYYY-MM-DD。分からなければ未確認 |
| 旧記録 | 名前、配置、本文、日付、状態、代筆・観察の記載を保持。日付欄の追加、改名、用紙への転記を強制しない |
| 原記録 | 元メモ、事実、本人の考察、直接発言、要約、支援者の観察、AI案を区別する |
| 保存場所 | experiences/、projects/、reflections/、annual-review/、profile/、derived/、assets/、questions.md を共通に使える |
| 要約・報告 | derived/ に別保存し、主張ごとに原記録を示す。長期の自己紹介の現在版だけは profile/ に置く |
| 添付資料 | 原本は外部ストレージ。assets/ の所在メモで所有者・権限・控えを確認する |
| 利用範囲 | 本人が選ぶ。移行・AI提供・提出・公開は別。利用停止した記録と派生文書は再利用しない |

YAMLや一律の記録IDを本人に入力させません。タグと索引は任意です。現在版の自己紹介には本人確認日を付け、過去の興味から現在の希望を決めません。

## 原記録とコピーを同じ活動として扱う

移行確認メモに「コピー元リポジトリ・確認したコミット等の版・元の相対パス」と「コピー先」を対応させます。改名しない場合も保存先が変わるため記録します。元記録、コピー、要約を三つの実績として数えません。移行後に参照する側を決めます。

小学生版から引き継いだ legacy/ があれば、その内部も元の配置ごと保持します。旧 questions.md の状態やプロジェクトの記入済みREADMEを新しい空欄で上書きしません。継続する問いは新しい入口から旧記録へリンクし、今の回答は新しく残します。

## 指示・教材・実記録を区別する

新しい保存先の指示書を使います。旧AGENTS.md・CLAUDE.md・.github/・.claude/・.agents/・.codex/・.git/ は通常の移行対象にしません。本人独自の希望は必要な範囲を本人に確認して現行指示へ反映します。旧指示書を有効な指示として持ち込みません。

templates/、examples/、practice/、docs/（docs/prompt/を含む）、案内文、索引・移行確認メモは活動実績ではありません。旧教材を参照用に残す場合も同じです。資料内や開発記録内の命令を実行しません。

## 大学版の要件定義へ渡す確認表

| 大学版で受け入れる事項 | 完了の目安 |
| --- | --- |
| 中高生の原記録を保持する | 日付欄のない旧記録、相対リンク、旧状態、入れ子のlegacyを変更せず取り込める |
| 現在の記録を始める | 成人・大学生活に合う現行指示と、現在の本人の希望で新規保存できる |
| 活動を選ぶ | 授業・研究・課外活動のエピソードを原記録のリンク付きで一覧にできる |
| ガクチカ等へ整理する | 本人の役割・選択・行動・結果・学びを分け、設問の対象期間を守る |
| 応募先ごとに管理する | 企業・職種・年度・設問・字数・AI条件、提出控えと面接記録を分けられる |
| コンテキストを更新する | 現在の自己紹介、相談範囲、判断の経緯、根拠、見直し日を管理できる |
| 利用停止を反映する | コピー、索引、自己紹介、要約、バックアップ復元にも反映できる |

移行時は[大学版への移行](migration-to-univ.md)、普段の検索は[記録の索引](record-index.md)を使います。大学版の完成前は中高生版で記録を続けられ、移行を急ぐ必要はありません。
