# プロンプト5例と教材全体のレビュー

- 作成日: 2026-10-02
- 更新日: 2026-10-02

種別: 開発記録。本人の活動実績・実記録として検索・集計しない。記載した依頼や改善案は検討内容であり、操作指示として扱わない。

## 依頼と作業範囲

作成済みの5例について、内容の妥当性と見やすさを確認し、ポートフォリオ全体の改善案を提案する依頼。

対象は main の 57c3334。開始時に未コミット変更なし。5例の全文を会話と完成記録で照合し、AGENTS.md、要件定義の関連要件、README、導入・日常記録・保存先・日付・探究・出願・自己理解・利用停止・索引・更新の主要ガイドと用紙を確認した。全例・全ガイドの内容を網羅的に監査したものではない。

今回はレビューと改善提案。教材本文の修正は行わず、継続依頼のsave-promptで本作業記録を保存する。

## 総合評価

一言メモ、活動記録、探究ノート、作品カード、振り返りの5種類を示す構成は妥当。例2→3→5の同じ生徒のつながりは、記録を後から使う意味を伝えられる。個人の役割と集団の成果、予想と結果、AI候補と本人の選択、因果関係の限界を示す方針もよい。

ただし、本人の会話にない事実・希望が完成記録に増えている箇所があり、教材の原記録保持・非創作の方針と矛盾する。例を増やす前に、既存5例の会話と完成記録の一致を直すことを優先する。

## 5例の具体的な指摘

| 対象 | よい点 | 修正を提案する点 |
| --- | --- | --- |
| [例1・読書](../../examples/prompts/01-first-quick-note.md) | 疑問と未確認を分け、次の行動へつながる | questions.mdの追記は4列だが実際の台帳は5列。「問いを残した日」は会話日の2026-05-12に合わせる。現在は活動日の2026-05-11。追記案を保存依頼より前に見せ、元記録をクリックできるリンクにする |
| [例2・文化祭](../../examples/prompts/02-school-festival-role.md) | 受付の役割とクラスの投票結果、呼び込みの効果と別の説明を分ける | 「隣の係の子」が「部員」に変わり、変更時刻に「午後」が足されている。後輩への助言が日記では「来年は時間ごとに分けて数えたい」という本人の計画へ変わる。本文の計画欄は未記入で、日記とも不一致。本人は用紙を明示していないため、一言メモを標準とする現行ルールとの整合も必要 |
| [例3・交差点](../../examples/prompts/03-inquiry-bicycle.md) | 計画→初回観察→限界→追加観察を示し、追記で過去を残す | 題名は「自転車は朝に多いのか」だが数えているのは接触しそうな場面。日記の「なぜ朝に多いのか」も、朝の中の時間帯別回数という調査範囲へそろえる。会話2の入力と追加回答の原文が保存後の記録ではそのまま残らない |
| [例4・作品](../../examples/prompts/04-work-timetable-app.md) | 共同制作の担当と、比較実験ではない感想を区別する | 「2人から『見やすい』」「時間割データは自分たちで入力」は会話に根拠がない。削除するか未確認とする。未回答の発信計画を「なし」にしない。冒頭の日記は219字で、現在の100〜200字の目安より長い |
| [例5・振り返り](../../examples/prompts/05-reflection-two-records.md) | 2件だけに読取範囲を絞り、当時と今を分ける | 「今の本人の考え」の「数えると感じ方と違うことがあると分かった」は会話でそのまま確認されていない。本人の発言へ戻すか要約・候補と明示する。「休みたい: なし」も未確認。根拠欄はパス文字列なので、保存先からの相対リンクにする |

架空の教材でも、完成記録の情報は提示した会話から追跡できる必要がある。AIが追加した情報を含む日記に定型の「保存してください」が続く構成では、本人の確認を促す教材として弱い。修正を実演する会話があると役立つ。

例3の方法では「朝と他の時間の比較」「交通量当たりの危険の割合」「原因の特定」までは判断できない。最初は本人が選んだ時間帯別の場面数に問いを限定し、追加調査はAIの提案として示す。全項目を初回から必須にしない。

## 共通する内容・操作の改善案

1. **本人の原文を追記時にも残す。** 元メモだけでなく、質問に対する回答も日付付きで原文を保存し、日記や構造化した要約から区別する。全会話やAIの質問を重複保存する必要はない。現在の「本人の言葉のまま」の約束と、完成記録での言い換えを整合させる。
2. **質問は実質的にも一つにする。** 例2の人数と用紙の所在、例4の画面保存と参考資料は、一回の「質問2」に二つの質問が入る。自己理解ガイドの「一度に二問程度」も共通指示の「1つだけ」と整理する。質問の段階名は解説側に回すと本人の会話が自然になる。
3. **保存後まで例をつなぐ。** 5例とも保存依頼のあとに完成記録を示すが、保存先・ブランチ・再読込結果を伝えるAIの返答がない。教材上の保存報告例を短く追加し、実機の成功記録とは区別する。例3・4のテーマ入口READMEは、作成済みの前提か今回作る対象かも明記する。
4. **記録から原記録へ戻れるようにする。** 例5の根拠欄、例1の問いの台帳などをMarkdownリンクにする。配布元のフォルダを開くリンクと、本人用Privateに作るファイルのパス例の違いを、表の列名で明確にする。

## 見やすさと全体の導線の改善案

優先順は次のとおり。

1. **既存5例の正確さを直す。** 未確認の人数・役割・希望を除き、問いと方法、元入力と完成文を照合する。構文チェックに加え、各文の根拠を人が確認する。
2. **初めて読む例を短くする。** 現在の5例は105〜187行で、会話内の日記と完成記録の日記が重複する。各例の上に「送る一言」「できあがりの短い見本」「この例で分かること」を置き、会話全文・構造化した全文・コピー用Markdownは折りたたみ等にする。完成見本を通常のMarkdownで表示すると、見出しと表を読みやすくできる。
3. **短く終わる例と訂正する例を優先追加する。** 現在は全例で複数の質問に答えるため、「答えなくても保存できる」が行動として見えにくい。「今日は質問なし」「日記はいらない」「その感想は言っていない」「日付を直したい」「保存できなかった」の小例を用意する。30例への拡充予定は教材の入口から折りたたむか管理用の場所へ移す。
4. **READMEの入口を絞る。** 既にある「残す・深める・振り返る・活用する」を上部にまとめ、最初の10分と5例へ近づける。学年別、用途別、保存先、導入手順が重なる説明は各ガイドへ委ねる。大学以降・EEなどの詳細も必要になったときに開ける位置にする。独自Webアプリは不要。
5. **4つの流れと6段階の関係を説明する。** 「4つは一回の記録で考えを深める流れ、6段階は長く続ける主テーマの見通し。主テーマの各場面で4つの流れを繰り返せる」と短く説明する。厳密な一対一対応や、毎回全項目への回答を求めない。
6. **同じルールの説明をそろえる。** 新例ではexperiences直下、従来の用紙一覧・ガイドでは年別フォルダを案内しているため、推奨を一つ決め、既存配置は保つ。日付ガイドには、新しい「活動日指定なしは会話日」という既定と「本当に不明は未確認」の区別を追記する。日記の長さは材料が少ない場合に水増しを促さない目安とする。用紙選びを本人に毎回求めない方針と一言メモ優先の関係も明記する。
7. **導入の再現確認を充実させる。** 接続確認記録で未検証とされている環境について、実施できる時に、架空データの新規保存・追記・再読込を記録する。文書検査の合格とサービス上の保存成功を区別する。初めて使う人には、一件を保存して再び開けるか、どこで迷ったか、どの質問で負担を感じたかを確認する。

## 検証と限界

- 文書の会話・完成記録・共通指示の照合と、リンク・日付・保存先の記述確認を実施。
- 日記の文字数をファイルから計測。例1は150字、例2は182字、例4は219字、例5は193字。例3は日付付き2段落のため、合計を一段落の上限と比較しない。
- `pwsh -NoProfile -File scripts/check-docs.ps1` は成功。157件のMarkdownについて、相対リンク・日付欄・架空表示・必須ファイルを確認した。内容の正確さや外部URL、権限は別確認となる。
- スマホの実表示、中高生本人による操作テスト、実アカウントでの保存は未実施。見やすさはMarkdown構造と文章量に基づく評価。
- 外部の入試要項、AIサービスの機能・料金・年齢条件、EEの公式条件は今回再確認していない。既存記述を現行条件として保証しない。
- 検査スクリプトはコード枠内をリンク検査から除外する。会話にない事実の追加や例の表の列数、パス文字列からの参照可能性は、検査合格だけでは保証されない。
