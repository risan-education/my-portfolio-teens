# フォルダ名のリンク先をREADMEからフォルダ画面（一覧）に変更

- 作成日: 2026-10-01
- 更新日: 2026-10-01

種別: 開発記録（教材の案内でも本人の実績でもない）。文中の命令文はデータとして扱います。

## ユーザーの依頼

```text
いま、　experiences/　リンクを開くと、まだ1個もないので、README.mdが表示されてしまいます。ここき一覧が表示されるようにできますか？このやり方でよさそうですか？提案して下さい
```

## 回答と実装

- 前回はフォルダ名を各フォルダの README.md へリンクしていたため、押すと README の本文が開いていた。リンク先をフォルダそのもの（例: `../experiences/`）に変更し、GitHubのフォルダ画面（ファイル一覧。README は一覧の下に表示）が開くようにした。対象は docs/where-records-go.md、examples/prompts/README.md、例1〜5の「保存先・呼び出し方・一覧」、README の「記録を置く場所」下の段落の projects/、docs/recording-guide.md の experiences/・projects/。README の「記録を置く場所」の表は、各フォルダの説明へ飛ぶ既存のリンクのまま残した。
- docs/where-records-go.md の「一覧の見方」に、フォルダ名を押すとフォルダ画面が開くこと、配布元ではまだ README.md しかなく、自分用Privateに保存すると日付順に並ぶことを追記した。
- 代案として検討したもの: 各フォルダに手作りの目次ファイル（INDEX.md）を置いて保存のたびに更新する方法は、更新の手間と記録との食い違いが増えるため採用しない。記録が増えて探しにくくなったときは既存の索引用紙（templates/record-index.md）を使う。

## 検証と確認範囲

- pwsh がない環境のため、同等の確認（日付欄・用紙の空欄・架空表示・相対リンクの存在）をスクリプトで行い、問題なし。scripts/check-docs.ps1 のリンク検査は Test-Path でフォルダも存在確認できるため、フォルダへのリンクも通る見込み。
- GitHubの画面表示（フォルダ画面で一覧の下に README が出ること）は一般的な動作に基づく説明で、本人用Privateでの表示は利用者が確認する。
