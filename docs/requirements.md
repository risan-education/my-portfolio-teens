中学と高校で分けない理由は、記録の継続、本人の経験・関心に合う深さの選択、共通部分の保守を優先するため。高校進学時にデータの移行や形式の変換を求めない。年齢条件、提出先、支援の必要性による違いはガイドと記入例で扱う。

## 2. 目的と利用者

本人の経験・問い・作品・考えの変化を一次情報として残し、後から自分の興味や次の行動を考えられるようにする。探究発表、進路探索、活動報告、面接準備、AIへの自己紹介にも、本人が選んだ記録を利用できる。

- 主な利用者: 中学生・高校生本人。GitHubやMarkdownの予備知識は前提としない。
- 支援者: 本人が希望する保護者など。支援者の観察・助言は本人の考えと区別する。
- 管理者: テンプレート配布元。実際の生徒の記録を集める運用は設けない。
- 成果の考え方: 記録数や受賞歴ではなく、残したい経験を保存でき、後から根拠に戻って振り返れること。

## 3. 初版の範囲

### 含めるもの

- 日本語のREADME、用紙、架空例、初回設定と日常利用のガイド。
- 手入力による記録と、任意のAI支援による整理の両方。
- 個人用の非公開リポジトリへの複製・保存の案内。
- 小学生版の原記録を保持した引き継ぎ。
- 外部ストレージに置いた写真・動画・PDF等の所在の記録。
- 記録のバックアップ、復元、利用停止・削除、テンプレート更新の案内。
- 任意で使う進路探索、提出条件確認、活動報告・面接準備の材料整理。
- 任意で選べる6段階の探究プロジェクト用紙、進行ガイド、AI相談例、架空の継続記録例。

### 初版の対象外

- 独自のWebアプリ、ログイン機能、データベース、外部サービスとの自動同期。
- 学校・塾のクラス管理、一括提出、教員による採点・学習分析。
- 生徒のランキング、性格・能力・合格可能性の自動判定。
- 記録の自動公開、外部提出、共有権限の自動拡張。
- 特定の有料AIの契約を必要条件とする運用。

## 4. 利用の入口

READMEでは次の四つの目的から選べるようにする。順番に進む必修課程ではなく、いつでも行き来できる。

| 目的 | 主な用紙 | 利用例 |
| --- | --- | --- |
| 残す | 一言メモ、活動記録、作品カード | 部活で気づいたこと、読書、行事、趣味、作品 |
| 深める | 探究ノート、問いの一覧、6段階の探究プロジェクト | 疑問を調べる、試す、方法を変える。必要なテーマでは現場検証・発信・協働まで進める |
| 振り返る | 振り返り、年間振り返り | 興味や考えの変化を元記録と比較する |

## 5. 記録の要件

| ID | 要件 |
| --- | --- |
| R-01 | 一言メモは短文だけでも保存できる。記録の頻度、最低文字数、連続記録を要求しない。 |
| R-02 | 活動記録は「何をしたか・なぜ取り組んだか・どう考え工夫したか・何が分かったか・次にどうしたいか」を基本の観点とする。空欄を認める。 |
| R-03 | 活動日、記録日、ファイルの作成日・更新日を区別する。日付や数値が不明なら推測せず未確認とする。 |
| R-04 | 本人の入力メモ、実際の発言、事実、本人の考察、支援者の観察、AIの提案を区別する。本人の直接発言と要約を混同しない。 |
| R-05 | 自分の役割と集団の成果、計画と実施済みの活動、予想と結果を分けて書ける。 |
| R-06 | 写真・作品・資料の所在や出典を記録できる。参考資料の内容と本人の考えを区別する。 |
| R-07 | 訂正・追記は日付と理由を残し、当時の考えを後からの解釈に置き換えない。本人による利用停止・削除の希望は別途扱う。 |
| R-08 | 必要な記録を年・テーマ・タグ・リンクから探せる。タグ付けは任意とする。 |

### 探究ノート

基本項目は、問い、本人の予想、調べ方・試し方、実施記録、結果と根拠、考えたこと、次の問い、資料とする。実験だけでなく、読書、制作、観察、聞き取りなどでも使える言葉を選ぶ。

追加質問は、方法を選んだ理由、別の説明、資料の信頼性、調べ方の限界、異なる立場の見方、別の場面とのつながりなど。中高どちらでも任意で使える。

状態は「これから・途中・ひと区切り・お休み」を表せるようにする。結論が出ないこと、中断、予想に反する結果も記録できる。

### 6段階で進める探究プロジェクト（任意）

[参考記事「推薦入試対策としての高校での探究活動のやりかた」](https://risan.jpn.org/?p=14459)の6段階に対応する。記事の段階構成をもとに、以下の記録項目と進行管理を本教材の独自仕様として設ける。

**仕組みの提供は初版の必須要件、利用するかどうかは本人の任意**とする。通常の一言メモ・活動記録・探究ノートと併用し、一つのテーマを複数回の活動で深める際に選べるようにする。

| 段階 | 本人が取り組むこと | 用紙で支援する記録 |
| --- | --- | --- |
| 1. 興味を見つける | 自分が気になることを見つける | きっかけ、興味を持った理由、関係する日常の記録へのリンク |
| 2. 課題を決める | 興味とつながる具体的な困りごとを絞る | 誰がどんな場面で困るか、取り組む課題を一文で、対象と範囲、選んだ理由 |
| 3. 仮説を立てる | 原因や解決方法の見通しを、資料と照らして考える | 本人の仮説、出典、まだ不明な点、何が分かれば仮説を確かめられるか |
| 4. 現場で確かめる | 観察・訪問・聞き取り・調査などを実施する | 方法と日程、質問や観察項目、実際の結果、仮説との差、方法の限界、資料の所在 |
| 5. 形にして発信する | 解決策を試し、作品や発表として伝える | 試作と改善、作品へのリンク、伝えた相手と方法、実際に得た反応、次に直す点 |
| 6. 人を巻き込む | 協力を得て活動を広げる | 協力先の候補と実際の協力者を区別、依頼・役割分担、自分の貢献、実施したこと、変化と根拠、今後の継続 |

#### プロジェクト単位の進め方

- `templates/inquiry-project.md` をコピーし、`projects/<theme>/README.md` をプロジェクトの入口にする。作成時に既存の同名フォルダを上書きしない。
- 入口には、テーマ、本人が取り組む理由、元の問い・活動記録、今取り組んでいる段階、次に本人が選んだ行動を置く。複数段階を並行して扱える。
- 6段階の一覧に「これから・途中・ひと区切り・お休み・今回は扱わない」の状態、最終更新日、実施記録へのリンクを持たせる。状態変更には日付と理由を残す。
- 段階ごとに「考え・計画／実施したことと日付／結果・根拠リンク／振り返り／次の候補と本人の選択」を分ける。計画を書いただけで実施済みにしない。
- 日々の詳細は従来の活動記録・探究ノート・作品カードを使い、入口からリンクする。同じ内容を6段階の用紙へ重複転記させない。
- 既存の記録を選んで途中から始められる。前の段階に戻る、繰り返す、課題・仮説を変更する、休むことを認める。変更前の考えも日付付きでたどれるようにする。
- 「ひと区切り」は本人が根拠を添えて判断する活動の状態とし、能力評価・合格判定・レベル認定には使わない。段階番号と大学群の対応表は実装しない。
- 外部への依頼や発信は計画と実施を分け、相手・共有する内容・必要な同意を確認する欄を置く。発信先は身近な相手や限定した場でもよく、インターネット公開を必須にしない。
- 進路と関連付けたい場合のみ、学びたい分野や進路探索シートへのリンクを追加する。6段階を使うために志望校を決める必要はない。

#### AIによる伴走

AIへの依頼例をガイドに用意する。「このテーマを6段階で進めたい」「この段階の次の一歩を相談したい」「調べた結果から仮説を見直したい」「活動報告の材料を整理したい」などの依頼に対応する。

AIは本人の考えと既存記録を確かめ、今回扱う段階に応じた質問や、具体的で取り組める次の行動候補を示す。候補と本人が選んだ行動を分け、本人が保存を依頼した範囲でプロジェクトの用紙へ反映する。毎回6段階すべてへの回答を求めず、先の段階への進行を強制しない。AIが仮説を提案した場合も、本人が最初から考えた仮説として書かない。

まとめるときは、課題を選んだ理由、本人の役割、仮説と検証、工夫・変更、成果と限界、次の問いを根拠付きで整理する。提出用途の場合は提出条件確認の要件を適用する。

### 振り返り・活用

振り返りには元記録へのリンクを付ける。現在の興味・希望は本人が確認し、過去の記録から自動的に決めない。進路が未定でも利用できる。

提出用の材料整理では、提出先・年度・設問・対象期間・AI利用条件を確認する欄を用意する。学校ごとの要件や合否の判断基準はテンプレートに固定しない。本人の確認を経て用途に応じて使う。

## 6. AI支援の要件

- AIを使わず手動で記録・整理できる。AIを使う場合は、質問、文章の整理、誤字修正、根拠付き要約などを支援する。
- 本人がしていない活動、言っていない発言、感じたか不明な感情、未確認の成果を創作しない。
- 整理前のメモを保持し、AIの提案は未実施として扱う。本人が選んだことを区別する。
- 要約・活動報告・AI向け自己紹介は原記録と別に保存し、根拠へのリンクを付ける。
- 空欄の用紙と架空例を本人の実績として検索・集計・要約に含めない。
- 少数の記録から性格・能力・将来の適性を断定しない。
- 本人が認めた利用範囲の情報だけを扱う。AIに渡さない情報は接続対象の外で管理する。
- 操作ガイドは、読取・編集・保存のどこまで確認できたかを明記する。下書きを示しただけで保存済みと案内しない。
- サービス別の年齢条件・同意条件・接続機能は、ガイド制作時に公式資料で確認し、確認日を付ける。

## 7. 保存・共有・継続

- 配布用には空欄の用紙と明示的な架空例だけを置く。本人の実記録は本人用のPrivateリポジトリに保存する設計とする。
- 本名、学校名、住所などを必須項目にしない。支援者・協力者は役割だけでも記録できる。
- 写真・動画等の原本は外部ストレージに置き、GitHubには所在メモを残す。リンクを知っていることと閲覧権限があることを区別する。
- 保護者にどこまで見せるか、何をAIに渡すか、何を提出するかは本人の希望を確認する。
- 学校アカウントを必須とせず、進学・卒業時の継続を考慮する。
- バックアップと復元は本文だけでなく、外部原本と参照リンクも確認する手順にする。
- 利用停止した記録は要約からも再利用しない。削除ガイドでは現在のファイル、Git履歴、コピー、外部原本の違いを説明する。
- テンプレート更新は本人の記録を上書きしない手順にする。

## 8. 小学生版との互換性

既存の `profile/`、`experiences/`、`projects/`、`reflections/`、`annual-review/`、`derived/`、`assets/`、`questions.md` を基本として引き継ぐ。

本人が残したい記録を選び、元のファイル名・日付・本文を保つ。小学生時代の文章や保護者による記録を、中高生向けの言葉へ一括変換しない。新しい振り返りは別ファイルにし、元記録へリンクする。

高校進学時の専用フォルダへの移動やテンプレートの切替は求めない。必要なら本文の学年欄やタグを任意で利用する。初版で自動移行プログラムは作らず、手順と架空の移行例を用意する。

## 11. 実装順序と未実施事項

1. 作成済みの公開リポジトリに、本書を `docs/requirements.md` として配置する。Template repository設定は配布準備時に確認する。
2. 共通フォルダ、README、一言メモ・活動記録・探究ノート・作品カード、6段階の探究プロジェクト用紙と進行ガイドを実装する。
3. 振り返り・活用の用紙、AI編集ルール、本人と支援者向けガイドを実装する。
4. 中高生の架空例、小学生版からの引き継ぎ例、6段階を使った一連の探究例と途中からの利用例を作る。
