# バックアップと復元

- 作成日: 2026-09-26
- 更新日: 2026-09-26

本文、外部原本、所在メモをセットで確認します。GitHubに文章があっても、外部の写真やPDFは一緒に保存されません。

ChatGPTに「自分の記録と外部原本のバックアップ手順を案内して」と頼めます。実際のZIPの取得、原本のコピー、控えが開くことの確認を終えるまでは、説明を受けただけでバックアップ完了とはしません。

## 控えを作る

1. 本人が保存を続けたい範囲を確認し、[利用停止した記録](record-choices.md)を再利用対象に戻さない。
2. GitHubでは対象ブランチの **Code → Download ZIP**、端末内ではフォルダのコピーで、日付付きの控えを別の非公開の場所に作る。ZIPはその時点の本文の控えで、Git履歴のバックアップではない。
3. 外部ストレージの写真・動画・PDFも別に控えを作る。資料名、ファイル名、原本と控えの場所、確認日、閲覧権限を所在メモに残す。
4. 控えからMarkdownと原本を開き、文字化けや欠落がないか確認する。ファイル数だけで判断しない。

## 復元する

1. 現在の記録を上書きしない、新しい確認用フォルダへ控えを展開する。
2. 復元する本文を開いて元の控えと比較する。利用停止・削除の希望がバックアップ後に出ていないか確認する。
3. 相対リンクをたどり、所在メモから外部原本を実際に開く。リンクが切れていたら、保存先とファイル名から控えを探す。見つからなければ「原本未確認」とする。
4. 本人が選んだ記録だけを非公開の保存先へ戻す。同名ファイルがあれば新旧を見比べ、無条件に上書きしない。
5. 復元した日、対象、本文の確認結果、外部原本の確認結果、未復元のものを別メモに残す。

Git履歴も必要な場合は、Gitを使える人が[公式バックアップ手順](https://docs.github.com/en/repositories/archiving-a-github-repository/backing-up-a-repository)のmirror clone等を検討します（確認日: 2026-09-26）。外部原本や共有権限まで自動復元されるわけではありません。この教材の検証は本文のZIP復元と模擬外部資料に限定します。

## 架空データで練習する

[探究例](../examples/inquiry-project/README.md)を別フォルダへコピーしZIPにして、さらに別フォルダへ展開します。[所在メモ](../examples/inquiry-project/materials.md)の架空パスを使う代わりに、テスト用の外部フォルダに無害なテキストを置き、その所在を別メモに書きます。復元後に本文とそのテキストを開けるか確かめます。配布例に実在の外部原本はありません。
